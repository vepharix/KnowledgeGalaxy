# 演示数据

这里存放 30–100 个 `KnowledgeEntity` 的研究数据、来源清单、抽样规则和生成说明。不要提交受限原文、个人数据或无法说明许可的大型抓取结果。

数据集必须刻意包含学科重叠、多个合理归属、粒度争议、关系方向不清和来源冲突。先制作 15–20 个实体的薄切片检验契约，再扩展到 Phase 1 规模；不要为了符合六类对象或四类关系而清理掉反例。

## 当前薄切片

`entities.json` 含 19 个对象：13 个数学概念、4 个定理/结构/方法、2 个理论物理边界对象，比例约为 68% / 21% / 11%。`sampleRole` 只用于检查抽样配额，不能解释为互斥本体类型。学科归属保留为可多选元数据，本轮文本模型不读取它。

英文定义由项目人工撰写，是所列公开来源的短篇释义，不复制来源原句。每条记录带来源 URL、许可、访问日期和使用说明。`definitionMayBeSentExternally` 只说明该英文字段可在操作者显式授权后用于外部嵌入对照；它不授权发送实体的其他字段。

`anchors.json` 含人工预先写下的相对近邻预期。每个锚点要求同一查询的 `closer` 得分高于 `farther`，但这些局部判断不是完整金标准。框架还会遍历全部实体对，报告两个模型给分差异最大的案例。

当前数据只用于跑通 15–20 个实体的薄切片，还未达到 Phase 1 要求的 30–100 个实体。图关系与元数据评价数据将在保持独立轨道的前提下另行加入。
