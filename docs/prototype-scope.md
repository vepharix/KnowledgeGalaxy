# Phase 1：两周知识模型研究范围

文件名暂时保留为 `prototype-scope.md` 以避免破坏现有链接；本阶段不是三维原型阶段。

## 研究结果

两周内完成一个包含 30–100 个 `KnowledgeEntity` 的建模实验。数据集要有意包含领域重叠和跨学科对象，使分类冲突、粒度不一致、关系歧义及不同径向模型之间的分歧显现出来。最终交付研究数据、证据记录、数据校验、至少两组候选模型的比较，以及下一阶段是否适合进入可视化的判断依据。

首轮问题域已经限定为几何、拓扑和微分几何，并加入少量理论物理边界对象。抽样目标约为 70% 数学概念、20% 定理/结构/方法和 10% 理论物理对象；这些只是保证样本构成的研究配额，不定义互斥实体类型。先以 15–20 个实体的薄切片检验框架，再扩展到完整规模。

实验载体为 Python 命令行工具和静态 HTML 报告。计算用的名称与定义以英文为主，报告解释以中文为主。模型默认本地运行；公开数学定义可在显式授权后发送给外部嵌入 API 作对照，不发送其他字段。

## 必须包含

- 选定一个天然跨学科的实验问题域，并写明纳入、排除和抽样规则。
- 收集 30–100 个候选实体；不要为了符合六类标签而删掉不合适的对象。
- 允许一个实体属于多个学科、拥有多个非互斥标签，或暂时无法分类。
- 为实体身份、分类和关系分别记录证据、不确定性及冲突来源。
- 至少比较两种实体粒度或身份划分方案，并记录合并/拆分差异。
- 分别表示层级、先修关系、语义相似与其他图关系，不以一个通用“距离”代替它们。
- 至少比较两种语义相似度定义，以及两种径向位置模型；其中可以包含“基础知识更靠近中心”假设，但不能把它设为默认真相。
- 首轮语义模型评价同时使用人工锚点预期和模型间最大分歧案例；锚点不是完整金标准，分歧也不自动表示任一模型错误。
- 文本相似、元数据和图结构使用独立输入、输出与评价，不形成未经验证的混合总分。
- 计算图连接性或中心性时，只把结果作为结构统计量，不将其命名为“基础性”。
- 形成模型失败案例清单：多学科归属、循环先修、来源冲突、粒度混杂和难以定向的关系应优先记录。
- 数据和实验过程可以重复运行；模型输出带方法名、版本和参数。

## 明确不包含

三维或二维可视化界面、时间轴交互、前端技术选型、运行时数据抓取、完整本体、自动权威判定、服务端数据库、账号协作、生产部署，以及把研究结果扩展到 200 个以上节点。

## 验收标准

Phase 1 完成时，另一位研究者应能从数据和来源中理解每个实体为何被纳入、分类和关系为何成立或仍有争议，并能重新运行候选模型得到相同结果。研究报告需要明确指出哪些对象使六类标签或四类关系失效，哪些模型产生相互矛盾的排序或距离，以及这些差异会怎样影响未来可视化。

本阶段不以“得到一张看起来合理的图”为验收标准。若实验结果表明单一中心、单一层级或统一距离无法表达数据，这也是有效结论。

## 建议节奏

| 工作日 | 可验证结果 |
| --- | --- |
| 1 | 确定研究问题域、抽样规则和对照假设 |
| 2–3 | 建立 15–20 个实体的薄切片，完成首次粒度与身份复核 |
| 4–5 | 扩展到 30–100 个实体，刻意补入跨学科和重叠案例 |
| 6 | 标注候选关系、证据、不确定性与冲突，不强行消解分歧 |
| 7 | 运行粒度、分类与语义相似候选模型比较 |
| 8 | 运行径向模型和图结构统计比较，检查错误解释风险 |
| 9 | 复核失败案例与数据质量，补齐可重复性检查 |
| 10 | 整理研究结论、仍未解决的问题和 Phase 2 进入条件 |

## Phase 2 进入条件

只有当至少一种实体身份方案和一组关系语义在实验数据上足够稳定，并且径向位置、语义距离与视觉距离的职责能够明确区分时，才讨论可视化原型。进入 Phase 2 不表示模型已经普适，只表示它足以支持一次有边界的交互实验。
