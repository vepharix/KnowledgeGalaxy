# Phase 1 数据契约草案

这不是产品数据库模式，也不是固定本体。它是一种研究交换格式，用来保存候选实体、可争议的断言、来源证据和不同模型的输出。字段是否保留，要由 30–100 个实体的实验决定。

## 需要分开的层次

| 概念 | 在研究中表示什么 | 不应被自动解释成什么 |
| --- | --- | --- |
| 本体 / 身份 | 某对象是什么、是否与另一记录指向同一对象 | 学科层级或空间位置 |
| 层级 | `is_a`、`part_of` 或学科分类中的上下位结构 | 学习先后或因果依赖 |
| 先修关系 | 理解或完成目标前通常需要哪些知识或能力 | 引用、年代更早或父类别 |
| 语义相似 | 在指定表示、语料和度量下的内容接近程度 | 事实关系、先修或视觉邻近 |
| 图连接性 | 在某组被纳入的关系断言中如何相连 | 概念基础性或知识重要性 |
| 径向位置 | 某个明确命名的“知识中心”模型给出的标量 | 图中心性、真理等级或固定视觉半径 |
| 视觉三维距离 | 布局算法为显示产生的欧氏距离 | 单一、稳定的知识距离 |

这些层次可以相关，但相关性本身需要实验，不写进契约的语义定义。

## 顶层研究包

候选顶层集合包括 `entities`、`assertions`、`evidence`、`modelRuns` 和 `metadata`。这是暂定拆分，实验允许发现遗漏。

### KnowledgeEntity

`KnowledgeEntity` 只保证研究包中的稳定身份引用，不保证对象天然就是图节点，也不要求互斥类型。

| 字段 | 暂定要求 | 说明 |
| --- | --- | --- |
| `id` | 必需 | 研究包内稳定、唯一，不暗含类型 |
| `names` | 必需 | 首选名与别名，允许跨语言 |
| `description` | 必需 | 当前研究语境下的简短说明 |
| `identityEvidenceRefs` | 必需 | 支撑身份划分或跨来源对齐的证据 |
| `facets` | 可选 | 非互斥候选标签；初始可观察六类标签但不限制于它们 |
| `disciplineAssertions` | 可选 | 指向学科归属断言，允许多个、重叠或冲突 |
| `temporalAssertions` | 可选 | 出现、发表、发明、应用等不同时间断言，不压成一个日期 |
| `granularityNote` | 必需 | 为什么把它作为一个实体，已知的合并/拆分替代方案 |
| `status` | 必需 | 如 `candidate`、`reviewed`、`contested`；枚举仍可调整 |

概念、论文、专利、工程成果、产品和历史事件可作为 `facets` 的初始值，用来检查它们是否有解释力。实验不得要求每个实体只选一个，也不得因无法归类而拒绝实体。

### Assertion

断言把研究判断与实体本身分开。同一主体和谓词可以有互相冲突的断言，各自连接证据。

| 字段 | 暂定要求 | 说明 |
| --- | --- | --- |
| `id` | 必需 | 稳定且唯一 |
| `subject` | 必需 | 主体实体或断言 ID |
| `predicate` | 必需 | 候选谓词；必须带词汇表版本 |
| `object` | 必需 | 目标实体、字面值或结构值 |
| `directionality` | 必需 | `directed`、`symmetric`、`undetermined` 等候选状态 |
| `evidenceRefs` | 必需 | 支持、反对或讨论该断言的证据 |
| `uncertainty` | 必需 | 结构化状态和文字理由；数值置信度不是默认要求 |
| `scope` | 可选 | 断言成立的时间、学科、语境或人群范围 |
| `curationMethod` | 必需 | 人工标注、规则推导、模型生成或来源直录 |

初始候选谓词包括引用、依赖、改进、应用、层级和先修，但它们不是封闭枚举。引用可能较容易定义方向；相似通常是对称分数；“依赖”“改进”“应用”和“先修”要先定义适用范围，不能仅凭词面共用一种边语义。

### Evidence

证据至少记录来源身份、定位信息、摘录或摘要、访问时间、许可/使用依据，以及它对某断言是支持、反对还是仅提供语境。多个来源冲突时全部保留，通过独立断言或证据立场表达，不覆盖成单一“正确值”。引用原文时遵守来源许可和必要限度。

### ModelRun

语义相似度、图统计、径向分数与未来布局都作为可重算的 `modelRun` 输出保存，不回写为实体事实。每次运行至少记录：

- `modelKind`：如 `semantic_similarity`、`graph_statistic`、`radial_model` 或未来的 `visual_layout`；
- 方法、版本、参数、输入断言集合和运行时间；
- 输出值及适用实体；
- 对缺失数据、方向性和冲突证据的处理；
- 已知限制及与其他候选运行的可比性。

径向模型必须显式命名“中心”是什么。例如候选模型可以以专家标注的先修深度、历史出现阶段或某种图统计量产生半径，但这些输出不能都叫“基础性”。“基础知识在中心”作为其中一个实验假设，与无单一中心、多中心或任务相关中心模型比较。

## 校验要求

Phase 1 至少检查 ID 唯一性、引用完整性、证据可定位性、模型运行可复现参数、断言方向状态存在，以及每个实体都有粒度说明。校验不要求六类标签完整覆盖，也不要求四类关系闭合。对于不确定和冲突数据，正确行为是保留并标记，而不是静默丢弃或强行选择。
